# Cleaning Log

One line per step: what changed, why, and how it was checked.

- **Step 1 – Combine price files:** Stacked the 11 PSA retail price CSVs (one per food category) into one table, skipping each file's title line and adding a `source_file` column with the category name. Why: basket items come from different files, and the category is only in each file's title line, so it would be lost when stacking. Removed `retailrprices.csv` first, because it was a duplicate of `comcrops.csv`. Check: 23,443 rows × 120 columns, which equals the sum of the 11 files' rows, plus the 1 new column.
- **Step 2 – Reshape wide to long:** Melted the 117 period columns into one `period` column and one `price` column, keeping `Geolocation`, `Commodity` and `source_file` fixed. Why: dates must be values, not column names, to filter by time, join to wages and query in SQL. Check: 2,742,831 rows × 5 columns (23,443 rows × 117 periods).
- **Step 3 – Remove "Annual" rows:** Dropped rows whose `period` contains "Annual". Why: they're PSA's yearly averages of the monthly values, not months, so keeping them would double count and block date conversion. Yearly averages can be recalculated from the monthly rows. Check: 2,531,844 rows remain (210,987 removed = 9 years × 23,443).
- **Step 4 – Convert prices to numbers:** Turned `price` from text into numbers with `pd.to_numeric(errors="coerce")`. PSA's "no price" placeholders `..` (1,740,216 rows) and `.` (70,329 rows) became `NaN`. Why: basket cost and hours of work need arithmetic, which text can't do, and pandas skips `NaN` in sums and averages. The missing rows are kept for now, because many will drop out once we filter to regions and basket items. Check: before converting, the only values without a digit were `..` and `.`. After converting, the type is `float64` with 1,810,545 `NaN` (= 1,740,216 + 70,329, about 71%), so no real price was lost.
- **Step 5 – Keep only regions:** Kept rows whose `Geolocation` starts with `..` but not `....`. This drops the national rows (`PHILIPPINES` / `Philippines`) and the province and city rows (which start with `....`). Why: minimum wages are set per region, so prices must be at region level to match the wage table. The national total would also double count the regions. Check: 18 regions remain (the usual 17 plus Negros Island Region), with 382,968 rows = 18 regions × 197 commodities × 108 months.
- **Step 6 – Standardize region names:** Mapped each PSA label to a short code (`NCR`, `IV-A`, `NIR`, …) and a readable name, and kept the official region order. Why: the wage table uses the same codes, so the join is exact. Check: the script stops if PSA ever adds a label that isn't in the mapping.
- **Step 7 – Drop rows with no price:** Kept 171,517 priced rows, from 2018-01 to 2026-09. Why: empty months add nothing, and the file stays small enough to open in Excel. Saved as `data/processed/prices_regions.csv`.
- **Step 8 – Basket and gap filling:** Picked 12 items priced in (almost) every region from 2018. Four region-item pairs are never priced by PSA: eggs and red onion (VII), native garlic (NIR), monggo (IV-A). For those, `sql/01_basket_prices.sql` uses the average of the other regions that month and sets `is_filled = 1`. Why: every region's basket must contain the same items to be comparable.
- **Step 9 – Wage in force:** Each month uses the latest wage order effective on or before the 15th (`sql/02_basket_monthly.sql`). Check: NCR Jul 2025 uses NCR-25 (₱645) because NCR-26 started on 18 Jul.
